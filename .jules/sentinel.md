## 2024-05-15 - PrivacyModal Markdown Parsing Flaw
**Vulnerability:** XSS through Markdown block parsing. The Markdown parser logic assumed that any block starting with `<` was safe because `escapeHtml` escapes literal HTML strings provided by the user. However, internal inline markdown constructs (e.g., `**text**` and `[link](url)`) natively generate `<` blocks (e.g., `<strong>text</strong>`, `<a href="url">link</a>`). By injecting inline HTML constructs *within* these native markdown features or tricking the fallback `!block.startsWith("<")` check, the parsed block avoided explicitly getting wrapped in `<p>` tags, opening potential vectors or semantic errors that rendered raw markup depending on context parsing down the line.
**Learning:** Checking if a string *starts* with a specific character (like `<`) is an unreliable way to infer its source or safety, especially in multistage parsers (escape -> convert blocks -> construct HTML). `escapeHtml` prevents literal `<` tags from getting through, but internal logic generating `<` tags must be strictly and exhaustively allowlisted to prevent unintended logic fall-through.
**Prevention:** Rather than using a negative check (`if (!block.startsWith("<"))`), use an explicit positive allowlist for known block tags generated by the parser (`if (block.startsWith("<h") || block.startsWith("<ul"))`), and strictly default to fallback sanitization/wrapping for all unhandled cases.
