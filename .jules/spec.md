## 2026-03-06 - Suppressing console.error in tests\n**Learning:** When tests deliberately throw errors (like simulating a network failure) that are caught and logged using `console.error` by the application code, Vitest prints these errors to the test output, creating messy logs. To prevent this, `console.error` should be mocked using `vi.spyOn(console, 'error').mockImplementation(() => {})` and restored afterwards.\n**Action:** Updated multiple tests to suppress expected `console.error` output, keeping test logs clean.
## 2026-03-07 - DOMParser Mocking Quirk\n**Learning:** When testing DOMParser usage for entity decoding in a Vitest Node.js environment, the `DOMParser` mock needs to return objects that resemble a real DOM structure (i.e. `{ documentElement: { textContent: '...' } }`). The application logic in `PrivacyModal.js` accesses `doc.documentElement.textContent || clean`, so the mock must explicitly cover cases where `doc` is `null`, `doc.documentElement` is `undefined`, or `doc.documentElement.textContent` is missing, to achieve 100% branch coverage.\n**Action:** Add targeted unit tests inside `tests/privacy-modal.test.js` testing `DOMParser` with mocked incomplete documents, and lock in the 0.11% branch coverage gain.
